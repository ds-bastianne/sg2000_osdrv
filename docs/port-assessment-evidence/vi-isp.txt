userspace_contract: All image-quality intelligence lives in userspace. (1) 3A: no AE/AWB/AF code in the kernel — the VI_IOCTL_AE_CFG/AWB_CFG/AF_CFG IDs are unhandled (grep 0 case labels); the kernel only DMAs statistics (AF, GMS, AE_LE/SE histograms, AWB, AWB_POST, DCI, HIST_EDGE_V, MMAP) into two banks of memblocks whose paddrs are published by VI_IOCTL_STS_MEM (struct cvi_isp_sts_mem vi_isp.h:233-245; vi.c:5428-5460) with a busy-index handshake STS_GET/STS_PUT and POST_STS_GET/PUT (vi.c:5004-5040,5389-5426) and wakes userspace via POLLPRI events (VI_EVENT_PRE*_SOF/EOF, POST_EOF, AWB*_DONE vi_uapi.h:121-139). (2) Tuning: userspace fills double-buffered tuning nodes (TUNING_NODE_NUM=2, per-block 'update' flags) in struct cvi_vip_isp_{fe,be,post}_cfg — measured sizes fe 212 B, be 33268 B, post 94852 B (47424 B per node) via host compile of vi_tun_cfg.h; ~80 config structs over 1472 header lines — written into kernel kzalloc'd memory addressed by physical address returned from VI_IOCTL_GET_TUN_ADDR (vi_tun_ip_ctrl.c:246-298 virt_to_phys; vi.c:5627-5643, which also copies kernel virtual pointers post_vir/be_vir/fe_vir to userspace). The kernel applies them at frame boundaries from the SCHED_FIFO 'cvitask_isp_pre' kthread (pre_fe/pre_be/postraw_tuning_update vi.c:7172-7190 -> ispblk_*_tun_cfg vi_tun_ip_ctrl.c:431-2444) and keeps a backup copy for resume (vi_tun_ip_ctrl.c:301-372). How userspace maps that physical address is not visible in osdrv (no mmap in sys.c; likely /dev/mem) — unverified. (3) Sensor control: sensor drivers are userspace libraries; exposure/gain register lists are pushed per frame (VI_IOCTL_SET_SNR_CFG_NODE, struct snsr_cfg_node_s vi_snsr.h:120-158; vi.c:5159-5200) and the kernel fires them at SOF or vblank through snsr_i2c (vi.c:1828-1950,7248-7262). Sensor format/WDR geometry also comes from userspace (VI_IOCTL_SET_SNR_INFO vi.c:5202-5226). (4) Shared memory: struct cvi_vi_ctx (dev/pipe/chn attributes, status counters) is mmap'd and mutated by both sides (cvi_vi_ctx.h:14-66; vi.c:4894,5875-5903). (5) Binary compatibility concerns: packed ioctl struct with embedded pointer (vi_uapi.h:128-137), physical addresses and kernel pointers in the ABI, dependence on vendor ION uAPI for every DMA buffer, and a 4376-byte shared struct layout. The CVITEK middleware (libisp/libae/libawb/libaf/libsys/libvi) is only available as the SDK's binaries/sources outside these repos; whether a buildable open-source copy (e.g. 'cvi_mpi') exists could not be checked (github.com blocked) — unverified. Structural fit is good: (a) statistics are already DMA'd by hardware into fixed-size memblocks (AF/GMS/AE/AWB/DCI/HIST/MMAP, vi_isp.h:233-245) -> META_CAPTURE buffers; (b) tuning is already a double-buffered, per-block 'update'-flagged struct applied at frame boundaries (vi_tun_cfg.h:1432-1448; vi.c:7172-7190) -> directly analogous to RKISP1 extensible params with per-block enable/disable headers (rkisp1-params.c:1736-2120) and to libcamera's params/stats IPA model; (c) the register-programming layer is cleanly separated (vip/*_ip_ctrl.c ~9.0k lines with near-zero kernel API use: 0 kernel-API hits in vi_be/vi_raw/vi_yuv/vi_subsys/vi_ip_test_case, 2 in vi_drv.c/vi_fe/vi_rgb, 14 slab hits in vi_tun_ip_ctrl.c; plus 28.3k lines of generated register headers) and can be reused as-is behind a V4L2 shell. Mismatches: (1) pipeline is multi-pass and time-multiplexed — 3 FEs feed one BE and one post stage through DRAM (fe->be->dram->post default for single sensor, vi.c:_vi_scene_ctrl single-sensor branch; fe->dram->be->post for dual RGB) — so the ISP subdev must model M2M scheduling like pisp_be rather than rkisp1's inline flow; (2) the hardware 'online to VPSS scaler' handshake (is_offline_scaler, VPSS_CB_VI_ONLINE_TRIGGER) requires the VPSS scaler to be a subdev in the same media graph or must be dropped (offline-to-DRAM is the default: vi.c:4605); (3) sensors are userspace in the vendor stack (vi_snsr.h cfg nodes) and would become in-kernel V4L2 subdevs with the CIF module as a CSI-2 receiver subdev; (4) the per-frame params block is large (47 KB post node) and would need an extensible/blocked uAPI design and a libcamera IPA plus open 3A algorithms, none of which exist for this ISP; (5) VB-pool/ION buffer ownership (vi_sdk_layer.c:77-125) is replaced by vb2 dma-contig (drivers/media/common/videobuf2/videobuf2-dma-contig.c) on a dma-noncoherent device (sg2000.dtsi:21, T-Head CMO errata present). Quantified: register programming .c 9046 lines (+1056 header lines, +28319 register-description header lines) is portable as-is; kernel-interface glue 11814 .c lines (+2069 header lines; vi.c alone 8229 with 1496 ISP_WR/RD macro uses and 362 ispblk_* calls) and 3094 uAPI header lines are what a V4L2 rewrite replaces.
