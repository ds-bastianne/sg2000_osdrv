userspace_contract: The kernel contains no panel knowledge: no DSI init tables exist in osdrv (grep for dsc_instr/panel tables finds only the struct definition cvi_comm_mipi_tx.h:12-17). Panel bring-up is driven by the CVI SDK middleware (libvo/sample code; not in this repo) through /dev/cvi-mipi-tx: CVI_VIP_MIPI_TX_SET_DEV_CFG supplies lane map/P-N swap, output format, pixel clock and full sync timing (struct combo_dev_cfg_s, vo_mipi_tx.h:55-66) and the kernel then programs D-PHY, DSI MAC, DISP timing and toggles the reset GPIO (vo_mipi_tx.c:148-234); CVI_VIP_MIPI_TX_SET_CMD sends each DCS/generic packet by raw data-type (vo_mipi_tx.c:257-276, 418-470; ECC/CRC done in kernel scaler.c:3877-3970); CVI_VIP_MIPI_TX_ENABLE switches to HS (vo_mipi_tx.c:298-302). For LVDS/BT/HW-MCU the whole interface config including raw GPIO numbers and MCU init instruction lists travels in VO_PUB_ATTR_S via VO_SDK_SET_PUBATTR (vo_sdk_layer.c:448-756; cvi_comm_vo.h VO_INTF_* bits :24-38). Frames reach the display either via SYS bind from VPSS (VB blocks pushed with vb_qbuf; base_context.c:712 wakes the VO 'cvitask_disp' SCHED_FIFO kthread vo.c:1030-1230) or explicitly via VO_SDK_SEND_FRAME, which looks the frame up by *physical address* (vb_physAddr2Handle, vo_sdk_layer.c:404); the VO keeps >=1 buffer on-screen and re-queues from the disp_frame_end IRQ (vo.c:2296-2340). Userspace also mmaps the 4 KiB cvi_vo_ctx shared state (vo.c:2139-2165) and reads /proc files. Single device/layer/channel only (VO_MAX_DEV_NUM = VO_MAX_LAYER_NUM = VO_MAX_CHN_NUM = 1, cvi_defines.h:312-315). Binary compatibility: a DRM port breaks all of this (different device nodes, ioctls, physical-address passing, mmap'd ctx); panel init moves into drivers/gpu/drm/panel/* selected by DT; frame handoff becomes dma-buf import (PRIME) + atomic page flips, and the fbdev users (/dev/fb0) keep working through drm_fbdev_dma but with XRGB8888 (or a fourcc chosen via drm_client_setup_with_fourcc) instead of the vendor default 16bpp ARGB4444 and without the 8-bit LUT mode. An out-of-tree compat shim re-implementing VO_IOC_*/mipi_tx ioctls over DRM would be a separate project and is not recommended.

mainline_framework_fit: Target framework: DRM/KMS (drivers/gpu/drm/sophgo/), not fbdev and not V4L2. Mapping: one drm_crtc = DISP timing generator + its DRAM fetch engine (mode set = sclr_disp_set_timing registers scaler.c:3179-3209; enable = DISP_CFG tgen bit scaler.c:3043; vblank = disp_frame_end bit of the SCL_TOP interrupt scaler.h:147-180; atomic flush = shadow-mask + force-update bit scaler.c:2249-2300, 3031-3035, which gives clean double-buffered register updates). Primary plane = DISP video layer: formats map directly to DRM fourccs (YUV420/422 planar, NV12/NV21/NV16/NV61, YUYV/YVYU/UYVY/VYUY, RGB888/BGR888 packed; vo_sdk_layer.c:24-170) with 64-byte stride alignment (VIP_ALIGNMENT vo_common.h:9), crop via DISP_OFFSET/SIZE and dst window via HMDE/VMDE (scaler.c:3253-3340); planar RGB and HSV formats have no fourcc and are dropped.
