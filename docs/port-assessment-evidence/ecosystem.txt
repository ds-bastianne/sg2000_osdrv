    topic: Q3 Armbian PR #10760: TPU driver port, ION -> dma-buf details
    finding: Patch 0064 'drivers: soc: sophgo: add CV181x/SG200x TPU driver' (author Wellken Chen <wellken.chen@cvitek.com.tw>, 2026-09-17) is a port of the vendor duo-buildroot-sdk-v2 (Linux 5.10) TPU chardev driver. Changes stated in its header: Android ION replaced by the standard dma-buf importer API, buffers come from the CMA dma-buf heap because the TPU has no IOMMU and needs physically contiguous memory; two new ioctls GET_DMABUF_PADDR / RELEASE_DMABUF expose a buffer's bus address (vendor ION exposed it, mainline heaps do not); cache maintenance uses dma_sync_sgtable_*() on the driver's own mapping instead of vendor-patched arch symbol exports; TEE paths dropped; 5.10 compat ifdefs collapsed; bounds-checking hardening. The chardev uAPI is kept binary-compatible with the vendor SDK so libcviruntime works 'with minimal changes' (a small allocator port in userspace). Implementation imports with dma_buf_get/dma_buf_attach/dma_buf_map_attachment_unlocked and rejects non-contiguous sg tables ('dmabuf is not contiguous (nents=%d), use the CMA heap'). Patch 0066 reserves a reusable 128 MiB default CMA pool on Duo S, replacing the vendor 170 MiB ION carveout. The patches are present in armbian/build main (2026-10-05), i.e. the PR is merged.
    evidence: /tmp/claude-0/-home-user/be69dd8d-dbf3-58dc-9770-31db5f4edebc/scratchpad/ext/armbian-build/patch/kernel/archive/sophgo-sg200x-7.3/0064-drivers-soc-sophgo-add-CV181x-SG200x-TPU-driver.patch lines 1-33 (header), 353-378 (dma_buf_get/attach/map, contiguity check, sg_dma_address), 1537-1583 (uAPI header, CVITPU_SUBMIT_DMABUF); 0066-riscv-dts-sophgo-reserve-a-default-CMA-pool-on-the-M.patch lines 1-12. PR page https://github.com/armbian/build/pull/10760 not fetchable (GitHub blocked), summary consistent with search snippet.
    confidence: verified
    implication_for_port: This is a proven recipe for removing the ION dependency shared by all osdrv modules (CONTEXT: cvi_ion_alloc/sys_ion_*): switch base/sys VB pools to the CMA dma-buf heap, import via dma-buf attach, export paddr through an ioctl, and replace arch_sync_dma_* exports with dma_sync_sgtable_*. The same author (a Cvitek employee) doing mainline ports is a possible collaboration lead. Estimate for applying this pattern to base+sys only: 2-4 engineer-weeks assuming the VB allocator stays a misc-device ioctl API and no uAPI redesign.
