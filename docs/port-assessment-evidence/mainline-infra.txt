    topic: Memory: dma-buf heaps uAPI and multi-region CMA support
    finding: Mainline ships exactly two heaps: system_heap.c and cma_heap.c; no 'carveout' heap exists (grep empty) and there is no in-kernel allocation API in include/linux/dma-heap.h (only dma_heap_add/dma_heap_get_name). cma_heap registers one heap for the default CMA area ('reserved' name) and one heap per additional dma-contiguous area, named after the reserved-memory node name, via dma_contiguous_get_area_by_idx(). A reserved-memory node becomes a CMA area only if it has compatible 'shared-dma-pool' + 'reusable' and no 'no-map'; up to CMA_AREAS (default 8) areas. uAPI is a single ioctl DMA_HEAP_IOCTL_ALLOC with heap_flags required to be 0. DMABUF_HEAPS_CMA depends on DMA_CMA; the riscv defconfig does not enable CMA/DMA_CMA/DMABUF_HEAPS.
    evidence: ls drivers/dma-buf/heaps -> cma_heap.c (425 lines), system_heap.c (548); grep -rni carveout drivers/dma-buf include/linux/dma-heap.h include/uapi/linux/dma-heap.h -> empty; include/linux/dma-heap.h:45-47 only dma_heap_get_name/dma_heap_add; drivers/dma-buf/heaps/cma_heap.c:397-421 add_cma_heaps (default_cma -> DEFAULT_CMA_NAME; loop dma_contiguous_get_area_by_idx(i) -> __add_cma_heap(cma, cma_get_name(cma))); kernel/dma/contiguous.c:55-84 dma_contiguous_areas[MAX_CMA_AREAS], dma_contiguous_get_area_by_idx EXPORT_SYMBOL_GPL; :505-515 __rmem_cma_verify_node requires 'reusable' and rejects 'no-map'; :560 cma_init_reserved_mem(rmem->base, rmem->size, 0, rmem->name, &cma); :589 RESERVEDMEM_OF_DECLARE(cma, "shared-dma-pool"); mm/Kconfig:1087-1088 CMA_AREAS default 8; include/uapi/linux/dma-heap.h:22 DMA_HEAP_VALID_HEAP_FLAGS (0ULL), :50-51 DMA_HEAP_IOCTL_ALLOC; drivers/dma-buf/heaps/Kconfig DMABUF_HEAPS_CMA depends on DMABUF_HEAPS && DMA_CMA; arch/riscv/configs/defconfig has no CMA/DMABUF lines.
