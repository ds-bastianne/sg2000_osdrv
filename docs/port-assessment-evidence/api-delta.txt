Mainline has no drivers/staging/android at all and the dma-heap in-kernel API only offers dma_heap_add/get_name/get_drvdata (include/linux/dma-heap.h:43-47, drivers/dma-buf/dma-heap.c:213-316), i.e. no in-kernel allocation entry point.

Mainline: `ls drivers/staging/android` fails; include/linux/dma-heap.h:43-47.

    implication_for_port: A replacement allocator has to be written inside cv181x_sys (reserved-memory/CMA backed, exporting dma-bufs via dma_buf_export, with its own buffer struct carrying paddr/vaddr/name) while preserving the exported sys_ion_* signatures so the other 10 modules stay source-compatible; the 5 direct ION users (sys.c, tpu, ldc_test, jdi.h, vdi.h) need patching.
