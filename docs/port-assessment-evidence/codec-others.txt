userspace_contract: CVITEK MPI middleware (libvenc/libvdec, libgdc, libive, TPU runtime, region library) is required and talks to the kernel exclusively through the ioctl ABIs listed in kernel_interface (81 codec ioctls, 47 IVE, 13 TPU, 7 DWA, 2+4 RGN, 5 rtos_cmdqu, 28 fast_image, 7 wiegand). Buffer handles are ION carveout PHYSICAL ADDRESSES passed by value (sys_ion_alloc_nofd returns phys addr, cvi_vc_drv/vcodec/vdi/linux/vdi.c:1886; TPU cache ioctls take paddr, tpu/common/cvi_tpu_interface.c:959-993), so switching to dma-buf fds changes the ABI and requires middleware changes or a compatibility shim. Algorithms living in the kernel: H.264/H.265 rate control (cvi_vc_drv/vcodec/cvi/cvi_enc_rc.c 657 lines plus common/rcKernel soft-float RC objects in cvi_vc_drv/Makefile:42-44), the whole Chips&Media host API (vpuapi 20,213 compiled lines) and even C&M sample/test helper code (vcodec/sample 8,220 compiled lines, VPU_InitWithBitcode called from main_enc_cvitest.c:528) - i.e. the kernel module contains what is normally a userspace codec library. VPU firmware blobs coda980.bin and monet.bin are read by the kernel from /usr/share/fw_vcodec at channel open (not /lib/firmware). TPU: compiled cvimodel command buffers submitted via ioctl with dma-buf fds, optional OP-TEE path. rtos_cmdqu/fast_image additionally depend on the FreeRTOS firmware on the C906L core (not in any repo) speaking the 8-byte cmdqu_t protocol. Binary compatibility: RISC-V 64 only; compat_ioctl present (10 sites) but irrelevant on rv64-only userspace. Dropping pwm/rtc/wdt/saradc in favour of mainline changes userspace from /dev/cvi-saradc ioctls to IIO sysfs, and RTC/PWM/WDT to standard class devices (sysfs/pwmchip, /dev/rtc0, /dev/watchdog0).
